# Day 2 — Zero-shot CLIP baseline on clean data

Date: 2026-09-05

## Objective (from execution plan)

Establish and freeze the "clean image" ceiling. Every later result (distorted,
rectified) gets measured against this number.

## Config

`configs/default.yaml` created with the 7 fields the plan specifies
(`model_name`, `pretrained_weights`, `class_names`, `prompt_template`,
`image_size`, `seed`, `dataset_root`). Values carried over unchanged from
Day 1's hardcoded constants (same model, same class-name spellings, same
default prompt). `image_size: 224` and `seed: 42` are recorded for
documentation/reproducibility but not actively used yet — Day 2 batch
inference is a deterministic single pass with no randomness, and preprocessing
is entirely `open_clip`'s own ViT-B/32 transform (no separate resize step),
per the "do not touch preprocessing beyond CLIP's own defaults" rule.

Dataset: all **1,514** MonuMAI images are used as the evaluation set (see the
Day 1 log and CLAUDE.md update for why "1,092" was stale and why there's no
train/test split to honor for a zero-shot-only, no-fine-tuning project).

## What was built

- `src/metrics.py` — `top1_accuracy`, `per_class_accuracy`,
  `confusion_matrix_counts`. General-purpose and reusable (Day 5/6 will need
  the same functions again), not Day-2-specific hacks.
- `src/clip_zero_shot.py` extended with a `--batch` mode alongside Day 1's
  `--image` mode:
  - Loads all 1,514 images once via `data_loader.load_monumai`.
  - Encodes every image's CLIP image feature **once** and reuses it across all
    3 prompt templates, rather than re-encoding the same 1,514 images 3 times.
    This is a deliberate CPU-throughput optimization, not a result-changing
    choice — the classification math (image feature · text feature, per
    template) is identical either way, since image features don't depend on
    the prompt.
  - Encodes each template's 4 class-prompt text features separately and
    classifies every image against them.
  - Writes one CSV per prompt template (image_path, true_label,
    predicted_label, correct, prompt_template, and one `score_<class>` column
    per class — all 4 softmax scores, since this is a 4-way task).
  - Saves the confusion matrix (as counts, via matplotlib) and a summary
    Markdown table (`results/tables/day2_baseline_summary.md`) with overall +
    per-class accuracy for all 3 templates.

## Exact prompts tried (Day 2 pilot — no winner picked yet)

1. `"{}"` (bare class name)
2. `"a photo of {} architecture"` (Day 1/2 default — this is the **clean
   baseline**)
3. `"a facade in {} architectural style"`

## Exact class-name spellings used

`Hispanic-Muslim`, `Gothic`, `Renaissance`, `Baroque` — taken verbatim from the
MonuMAI folder names on disk (see `src/data_loader.py`'s `STYLE_FOLDERS`), so
there is no separate spelling decision to make; `configs/default.yaml`'s
`class_names` list matches exactly.

## Results

### Clean baseline (prompt = `"a photo of {} architecture"`)

**Clean baseline accuracy = 61.43%** (930/1514 correct). This is the number
that gets defended in the paper and that Day 5's distorted/rectified numbers
are measured against. Well above the <35% stop-and-fix threshold (random
chance on this 4-way task is 25%), so no fix-and-reassess cycle is needed —
proceeding as planned.

Per-class accuracy (recall):

| Style | Accuracy |
|---|---|
| Hispanic-Muslim | 0.783 |
| Gothic | 0.705 |
| Renaissance | 0.785 |
| Baroque | 0.341 |

Confusion matrix: `figures/day2_confusion_clean.png` (generated by
`src/clip_zero_shot.py --batch`, from `configs/default.yaml`, no random seed
involved since inference here has no randomness).

### All 3 prompt templates (`results/tables/day2_baseline_summary.md`)

| Prompt template | Overall accuracy | Hispanic-Muslim | Gothic | Renaissance | Baroque |
|---|---|---|---|---|---|
| `{}` | 0.368 | 0.000 | 0.382 | 0.872 | 0.287 |

Per the plan, no winner is being picked here — this is only meant to show the

## One-sentence answer: best/worst style + hunch

CLIP (with the default prompt) is **best at Renaissance and Hispanic-Muslim**
(~78% each) and **worst at Baroque** (34%), and the confusion matrix shows why:
320 of 516 Baroque images (62%) are misclassified as Renaissance — a plausible
early hunch is that Baroque and Renaissance facades share a lot of visual
vocabulary (columns, symmetric arrangements, classical ornamentation) that a
CLIP text prompt built only from the class name can't easily separate,
especially since "Baroque" and "Renaissance" are both fairly generic
architectural-history terms without a strong single distinguishing visual cue
CLIP would have learned from web image-text pairs (unlike, say, the more
visually distinctive horseshoe arches associated with Hispanic-Muslim work).

## Surprising result — worth documenting, not hiding

The bare `"{}"` prompt (just the class name, no "a photo of... architecture"
framing) **completely fails on Hispanic-Muslim** — 0/? correct, i.e. 0.000
accuracy, with the confusion matrix (not shown above, but visible in that
template's own CSV) implying the model likely defaults to interpreting a bare
"Hispanic-Muslim" prompt very differently without the "architecture" framing
word (e.g., leaning on demographic/religious associations from its
CLIP-large-scale pretraining rather than an architectural style — this is a
hunch, not confirmed, and out of scope to dig into further right now). This is
a genuinely interesting/surprising number for the "Discussion & limitations"
or prompt-sensitivity section later, and it is exactly why the plan says not
to pick a prompt winner yet from just 1 template's numbers — a naive
"most information-dense" prompt choice (bare class name) can catastrophically
fail for reasons unrelated to architecture at all.

## Implementation note: a caught-before-logging bug

The first `--batch` run auto-generated output filenames by slugifying each
prompt template's text. For the bare `"{}"` template, every character is
non-alphanumeric, so the slug collapsed to an empty string, producing
`results/raw/day2_prompt_pilot_.csv`. Fixed by replacing the auto-slugify with
an explicit `PROMPT_TEMPLATE_SLUGS` mapping in `src/clip_zero_shot.py`, then
re-ran the full batch (deterministic — same 61.43% clean-baseline accuracy
both times, confirming the fix didn't change any numbers, only filenames).

## Runtime

Full `--batch` run (1,514 images encoded once + 3 templates classified against
the cached image features) completed in well under the ~30–60 minute estimate
the plan gives for the much larger Day 5 grid (9,828 forward passes) — this
run does only 1,514 image forward passes total (reused across templates) plus
3×4 cheap text encodes, on local CPU, no Colab needed.

## Success criteria check

or `results/tables/day2_baseline_summary.md`, per CLAUDE.md rule 6.
